# 🧪 Тестовая инфраструктура EORA

Этот документ описывает тестовую инфраструктуру проекта EORA, включая типы тестов, конфигурацию и способы запуска.

## 📋 Обзор тестов

Проект содержит комплексную тестовую инфраструктуру с различными типами тестов:

### 🔧 Типы тестов

1. **Юнит-тесты** - изолированное тестирование компонентов с моками
2. **Интеграционные тесты** - тестирование взаимодействия компонентов
3. **API тесты** - тестирование HTTP эндпоинтов через FastAPI TestClient
4. **Тесты безопасности** - проверка обработки вредоносных входных данных
5. **Тесты базы данных** - проверка работы с SQLite тестовой БД

## 📁 Структура тестов

```
tests/
├── conftest.py              # Конфигурация pytest и фикстуры
├── test_components.py       # Тесты компонентов (URLContentExtractor, RAGSystem)
├── test_main.py            # Основные API тесты (обновлены после рефакторинга)
├── test_escape_cleaning.py # Тесты очистки экранированных символов
├── test_db_connection.py   # Тесты подключения к тестовой БД
└── README.md               # Этот файл
```

## 📝 Описание тестовых файлов

### 1. test_components.py
**Назначение**: Тестирование отдельных компонентов системы

**Тестируемые компоненты:**
- **URLContentExtractor**: парсинг веб-страниц
  - Успешное извлечение контента
  - Обработка HTTP ошибок  
  - Валидация URL
  - Очистка URL
- **RAGSystem**: система поиска и генерации
  - Обнаружение спама/бессмыслицы
  - Валидация запросов
  - Поток генерации ответов
- **SourceURL модель**: работа с URL источниками
  - Валидация URL
  - Очистка и нормализация
  - Строковые представления
- **Утилиты**: вспомогательные функции
  - Очистка текста
  - Обрезка длинных текстов

### 2. test_main.py
**Назначение**: Основные API и интеграционные тесты

**Категории тестов:**

**🔹 Юнит-тесты (TestRAGSystemUnit)**
- Валидация запросов (валидные/невалидные)
- Генерация ответов с моками (обновлено после рефакторинга)

**🔹 Интеграционные тесты (TestDatabaseIntegration)**
- CRUD операции с SourceURL
- Связи между моделями SourceURL ↔ SourceContent

**🔹 Параметризованные тесты (TestParametrized)**
- Массовая проверка валидации запросов
- Различные сценарии входных данных

**🔹 Тесты безопасности (TestSecurity)**
- XSS атаки: `<script>alert('xss')</script>`
- SQL инъекции: `'; DROP TABLE source_urls; --`
- Template инъекции: `{{7*7}}`
- DoS атаки: очень длинные запросы (10000+ символов)

**🔹 Обработка ошибок (TestErrorHandling)**
- Невалидный JSON в запросах
- Некорректные форматы данных

### 3. test_escape_cleaning.py
**Назначение**: Тестирование очистки экранированных символов

**Тестируемые сценарии:**
- Экранированные кавычки: `\\"` → `"`
- Экранированные переносы: `\\n` → ` `
- Экранированные табуляции: `\\t` → ` `
- Двойные слеши: `\\\\` → `\\`
- Комбинированные случаи

### 4. test_db_connection.py
**Назначение**: Тестирование подключения к базе данных

**Функциональность:**
- **TestDatabaseConfig**: класс конфигурации тестовой БД
- **Типы БД**: in-memory SQLite (быстро) или файловая (персистентная)
- **Управление жизненным циклом**: создание → тестирование → очистка
- **Утилиты**: функции для использования в других тестах

## 🚀 Запуск тестов

### Основные команды

```bash
# Запуск всех тестов
docker exec eora-FastAPI python -m pytest tests/ -v

# Краткий вывод
docker exec eora-FastAPI python -m pytest tests/ --tb=line -q

# Только юнит-тесты
docker exec eora-FastAPI python -m pytest tests/ -m unit

# Только интеграционные тесты  
docker exec eora-FastAPI python -m pytest tests/ -m integration

# Исключить медленные тесты
docker exec eora-FastAPI python -m pytest tests/ -m "not slow"

# Тесты безопасности
docker exec eora-FastAPI python -m pytest tests/ -m security

# Конкретный файл
docker exec eora-FastAPI python -m pytest tests/test_components.py -v

# Конкретный тест
docker exec eora-FastAPI python -m pytest tests/test_main.py::TestSecurity::test_malicious_input_handling -v
```

### Дополнительные опции

```bash
# С покрытием кода
docker exec eora-FastAPI python -m pytest tests/ --cov=. --cov-report=html

# Параллельный запуск (если установлен pytest-xdist)
docker exec eora-FastAPI python -m pytest tests/ -n auto

# Остановка на первой ошибке
docker exec eora-FastAPI python -m pytest tests/ -x

# Повторный запуск только упавших тестов
docker exec eora-FastAPI python -m pytest tests/ --lf
```

```
✅ Тестовая БД готова к работе!

```

### 2. Выполнение тестов
- Каждый тест получает изолированную тестовую БД
- Моки настраиваются автоматически через фикстуры
- API тесты используют TestClient для HTTP запросов

```

```

## 🛠️ Особенности реализации

### Изоляция тестов
- **База данных**: каждый тест получает чистую in-memory SQLite
- **Моки**: автоматическое мокирование внешних зависимостей
- **Состояние**: тесты не влияют друг на друга

### Обновления после рефакторинга
- **API тесты**: обновлены для новой архитектуры без промежуточных функций
- **Моки**: переписаны для использования `initialize_rag_system` вместо `get_rag_system`
- **Импорты**: исправлены после перемещения констант

### Производительность
- **SQLite in-memory**: максимальная скорость тестов
- **Асинхронные тесты**: поддержка async/await
- **Параллелизация**: возможность запуска тестов параллельно

## 🔧 Добавление новых тестов

### Шаблон нового теста
```python
import pytest
import pytest_asyncio
from httpx import AsyncClient

class TestNewFeature:
    """Тесты новой функциональности"""
    
    @pytest.mark.asyncio
    async def test_new_functionality(self, test_client: AsyncClient):
        """Тест новой функциональности"""
        # Arrange
        test_data = {"key": "value"}
        
        # Act
        response = await test_client.post("/api/endpoint", json=test_data)
        
        # Assert
        assert response.status_code == 200
        assert "expected_key" in response.json()
```
